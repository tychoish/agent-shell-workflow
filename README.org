* Overview

~agent-shell-workflow~ provides dynamic workflow composition, template expansion,
and dispatching for ~agent-shell~ sessions. It enables structured workflow
authoring, file-based prompt templates, pre/post evaluation hooks, and ACR/Transient
interactive selection menus.

* Features

- *Workflow Templates*: Configurable variable substitutions with regex extraction.
- *Workflow Library*: Discoverable library of reusable workflow definitions (~agent-shell-workflow-library~).
- *Interactive Menus*: Completing-read workflow picker (~agent-shell-workflow-menu~).
- *Pluggable Dispatch*: Extensible target buffer resolution via ~agent-shell-workflow-dispatch-target-functions~ hook.
- *Zero Queue Coupling*: Works independently or alongside ~agent-shell-queue~.

* Display behavior

Each workflow controls how its shell buffer is presented, via =:display= (or
=:buffer-display=) in =register-agent-shell-workflow= or as a keyword to
=agent-shell-workflow-dispatch= (the dispatch argument wins; =:buffer-display= wins over =:display= when
both are given).  An unrecognized value is ignored.  When neither is given, ~agent-shell-workflow-default-display~ applies.

| Value                         | Alias    | Behavior                                      |
|-------------------------------+----------+-----------------------------------------------|
| =:foreground=                 | =focus=  | show and select the shell                     |
| =:display=                    | =show=   | show without selecting                        |
| =:background=                 | =bury=   | do not display; bury a newly created shell    |
| =display-buffer= action alist |          | passed to =display-buffer=                    |
| function                      |          | called with the shell buffer                  |

A =Workflow `ID' dispatched to DIR= message is shown in the echo area
when the prompt is delivered to a shell.  In the =register-agent-shell-workflow=
macro, quote an action alist (=:display '((display-buffer-pop-up-window))=).  Set ~agent-shell-workflow-notify~ to also send an =alert=
notification (skipped, with a message, when =alert= is unavailable).

=fix-ci= and =executor-pipeline-run= default to =:background=.
~agent-shell-workflow-dispatch-group~ shows at most the first repository's
shell (=:foreground= is downgraded to =:display=) and backgrounds the rest.

* Multi-repository workflows

A workflow can work across several repositories in two ways:

- *Together:* =(agent-shell-workflow-dispatch ID :repos '("/a" "/b"))= runs one
  session.  The first directory is the context directory (shell, debounce);
  every directory is in =:repos= for pre-ops and in the ={{repos}}= template
  variable, one per line.  Without =:repos=, =:repos= is the single context
  directory.  The =group-exec-all= library workflow uses this.
- *Iterate:* =agent-shell-workflow-dispatch-group= dispatches once per
  repository of a group (a symbol in ~agent-shell-workflow-repo-groups~ or a
  list of directories), each with its own context directory.  =group-exec= and
  =group-git-status= use this.  Pass =:together t= to dispatch-group to
  dispatch once with all of the group's repositories instead.
